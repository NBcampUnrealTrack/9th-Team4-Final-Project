# HUD 연동 요청 — 팀 배정·변경 알림

작성일: 2026-10-26
대상: 사용자님(Core), 명우님(매치메이킹·팀 배정 경로 협의)

## 목적

본인 또는 다른 플레이어의 팀 배정·변경 결과가 클라이언트에 도착하면 팀원 HUD 목록을 다시 조회할 수 있어야 합니다.

## 현재 확인한 구조

- `ANF_PlayerState::NF_TeamID`는 `Replicated` 속성이며 초기값은 `INDEX_NONE`입니다.
- `SetNFTeamID()`는 서버 권한과 1 이상의 팀 ID를 확인하고, 값을 설정한 뒤 `ForceNetUpdate()`를 호출합니다.
- 현재 팀 ID에는 `ReplicatedUsing` 또는 팀 변경 델리게이트가 없습니다.
- `Core/Match/NF_DedicatedMatchSubsystem.cpp`에서 `SetNFTeamID()`를 호출하는 팀 배정 경로가 있습니다.
- `UNF_TeamPanelViewModel`은 로컬 PlayerState와 같은 `NF_TeamID`인 플레이어만 표시합니다.

작성일의 C++ 소스 기준입니다. Core 영역의 연동 작업이며, 실제 배정 시점과 팀 규칙은 매치메이킹 담당과 협의합니다.

## 요청 사항

1. 최초 팀 배정과 이후 팀 변경이 클라이언트에 반영된 시점에 구독 가능한 알림을 제공해주세요.
2. 본인의 팀뿐 아니라 다른 플레이어의 팀이 변경되어도 해당 PlayerState와 현재 팀 ID를 확인할 수 있어야 합니다.
3. PlayerState가 목록에 추가된 뒤 팀 ID가 늦게 복제되어도 변경 알림이 발생해야 합니다.
4. 알림 처리 시 현재 `NF_TeamID`를 조회하면 새 값이 읽혀야 합니다. 이전 팀 ID도 제공 가능하다면 함께 알려주세요.
5. 서버와 클라이언트 양쪽에서 같은 알림을 사용할 계획이라면, 서버에서 값을 변경하는 경로의 알림 처리도 정의해주세요.
6. 무소속·배정 대기·팀 해제 상태의 값과 처리 규칙을 알려주세요. 현재 Setter는 1 미만의 값으로 팀을 해제할 수 없습니다. 해제가 필요 없다면 그 규칙을 확인해주시면 됩니다.

RepNotify와 델리게이트를 조합하는 등 원본 데이터 계층에서 알림을 제공하면 됩니다. 구체적인 이벤트 이름은 구현된 API에 맞춰 UI가 연결하겠습니다.

## UI 담당 범위

UI에서 본인·다른 플레이어의 팀 변경 알림을 구독하고 `RefreshMembers()`를 호출합니다. 팀 배정 판단, 팀 ID 설정, 서버 권한 검증은 Core·매치메이킹에서 담당합니다.

PlayerState가 교체되거나 제거되면 UI가 이전 알림 구독을 해제하고 새 대상에 연결합니다. 원본 시스템이 HUD나 ViewModel을 참조할 필요는 없습니다.

## 전달받고 싶은 내용

- 팀 ID 변경 이벤트와 조회 API
- 최초 배정, 재배정, 배정 대기 상태의 규칙
- 팀 배정 완료 시점과 명단 추가·제거 알림과의 관계
- 본인과 다른 플레이어의 팀 변경 수신 방법

## 완료 확인

- [ ] 본인의 팀 변경 시 이전 팀원이 제외되고 새 팀원이 포함됩니다.
- [ ] 다른 플레이어의 팀 변경도 관찰 클라이언트에 반영됩니다.
- [ ] HUD를 나중에 생성해도 현재 팀 ID로 목록을 복원할 수 있습니다.
