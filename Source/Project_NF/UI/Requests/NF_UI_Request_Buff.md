# HUD 연동 요청 — 활성 버프와 표시 데이터

작성일: 2026-10-25  
대상: 버프 / GameplayEffect 담당자

## 목적

현재 플레이어에게 적용 중인 버프를 식별하고, 담당자 데이터의 아이콘을 HUD에 표시하기 위한 요청입니다.

## 현재 확인한 구조

- `UNF_BuffDebuffViewModel`은 열쇠 소지 태그와 최대 실드 감소 태그만 구독합니다.
- 열쇠 소지 시 쿨타임 감소·피격 데미지 감소 아이콘을 함께 표시하는 구조입니다.
- 아이콘은 현재 VM Blueprint 기본값에서 지정하도록 되어 있습니다.
- 이 구조에는 일반적인 활성 버프와 담당자 소유 표시 DataAsset을 연결하는 경로가 없습니다.

위 내용은 작성일의 C++ 소스 기준입니다. 별도 Blueprint 전용 데이터가 있다면 그 조회 경로를 알려주세요.

## 요청 사항 — 정적 표시 정보

담당자가 관리하는 효과 관련 DataAsset에 다음 정보를 제공해주세요.

| 정보 | 용도 |
|---|---|
| 효과 식별자 | 활성 GameplayEffect 또는 GameplayTag와 표시 데이터 연결 |
| 아이콘 참조 | HUD 이미지 표시 |
| HUD 표시 대상 여부 | HUD에 표시할 효과 구분. 전용 표시 데이터 등록 여부로 구분해도 됩니다. |

효과 식별자는 기존 태그나 효과 정의를 활용해도 됩니다. 활성 상태에서 해당 DataAsset을 찾을 수 있는 공개 경로가 필요합니다.

이름·설명은 툴팁을 추가할 때 요청할 선택 정보입니다. 남은 시간과 중첩 수는 이번 필수 요청에 포함하지 않습니다.

## 요청 사항 — 실시간 상태

1. 최초 UI 연결 시 현재 활성인 HUD 표시 대상 효과를 조회할 수 있어야 합니다.
2. 효과 적용·제거를 클라이언트에서 구독할 수 있어야 합니다. 기존 ASC 이벤트를 사용할 수 있다면 해당 이벤트와 식별 규칙을 알려주세요.
3. 서버의 변경이 클라이언트에 반영된 시점에도 상태를 확인할 수 있어야 합니다.
4. 열쇠 드롭 등 효과 종료 시 관련 태그 또는 효과도 제거되어야 합니다.
5. 하나의 상태가 여러 아이콘을 의미하거나 여러 효과가 동일 아이콘으로 합쳐지는 경우, 그 대응 규칙을 알려주세요.

중복된 UI 전용 상태나 별도 Delegate를 반드시 만들라는 요청은 아닙니다. 기존 GAS 조회·이벤트로 충족 가능하면 그대로 사용하겠습니다.

## 데이터 흐름과 UI 담당 범위

```text
활성 효과·태그 + 담당자 표시 DataAsset
    → BuffDebuffViewModel의 표시 목록
    → FieldNotify
    → 버프 아이콘 위젯
```

UI에서 활성 상태를 구독하고 아이콘 목록을 구성·제거합니다. 현재 VM의 직접 아이콘 설정은 담당자 데이터 조회 방식으로 변경하겠습니다. 모델에서 VM이나 Widget을 직접 호출할 필요는 없습니다.

## 전달받고 싶은 내용

- 표시 DataAsset 클래스와 필드 또는 Getter 이름
- 활성 효과·태그에서 표시 데이터를 찾는 방법
- 초기 활성 상태 조회 방법과 적용·제거 구독 이벤트
- 값이 지정된 예시 에셋과 아이콘 대응 규칙

## 완료 확인

- [ ] 효과 종료 후 해당 아이콘을 제거할 수 있습니다.
- [ ] 아이콘 원본은 담당자 DataAsset에서 조회합니다.
- [ ] 상태 하나와 아이콘 여러 개의 대응 규칙이 명확합니다.
