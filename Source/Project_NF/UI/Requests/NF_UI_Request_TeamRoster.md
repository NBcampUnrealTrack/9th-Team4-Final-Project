# HUD 연동 요청 — 플레이어 입장·퇴장 알림

작성일: 2026-10-26
대상: 명우님(매치메이킹), Core 담당 협의

## 목적

게임 도중 플레이어가 들어오거나 나가면 팀원 HUD 목록을 갱신하기 위한 클라이언트 알림이 필요합니다.

## 현재 확인한 구조

- `UNF_TeamPanelViewModel::RefreshMembers()`는 `GameState->PlayerArray`에서 본인을 제외한 같은 팀을 조회합니다.
- `Members` 변경 이후 팀원 행 생성·제거와 각 행의 ViewModel 연결은 UI에 구현되어 있습니다.
- 현재 `RefreshMembers()`는 ViewModel 초기화 및 컨텍스트 변경 시 호출되며, 명단 변경 알림 구독은 연결되어 있지 않습니다.
- `Core/NF_GameMode.cpp`에 `PostLogin()`과 `Logout()` 처리가 있으며, `Logout()`에서 서버의 `OnMatchPlayerLeaving`을 알립니다.
- GameMode의 서버 알림만으로는 클라이언트 HUD가 직접 변경을 구독할 수 없습니다.

작성일의 C++ 소스 기준입니다. 세션 접속 처리와 실제 매치 내 명단 관리는 담당이 다를 수 있으므로, 명우님과 Core 담당 사이에서 알림 제공 위치를 먼저 확인해주세요. 기존 Core 처리를 매치메이킹 파트로 옮기라는 요청은 아닙니다.

## 요청 사항

1. 클라이언트에서 플레이어 목록 추가·제거를 구독할 수 있는 기존 알림이 있다면 클래스와 이벤트 이름을 알려주세요.
2. 없다면 복제 결과가 클라이언트의 현재 목록에 반영된 후 발생하는 알림을 제공해주세요. 제공 위치와 방식은 담당 파트에서 결정해주세요.
3. 알림 처리 시 `GameState->PlayerArray`를 다시 조회하면 퇴장한 플레이어가 제외되고, 추가된 플레이어가 포함되어야 합니다.
4. HUD가 늦게 생성되어도 현재 명단을 조회할 수 있어야 합니다. 과거 이벤트 재생 대신 현재 목록 조회로 복원할 수 있으면 됩니다.
5. 팀 ID가 명단보다 늦게 도착하는 경우는 별도 팀 변경 알림으로 재조회할 수 있도록 Core 담당과 협의해주세요.
6. 재접속·맵 전환 시 알림을 구독할 대상이 바뀐다면 재연결 시점을 알려주세요.

## UI 담당 범위

UI에서 알림을 구독·해제하고 `RefreshMembers()`를 호출합니다. 같은 팀 판정과 행 추가·제거는 UI에서 처리하므로, 원본 시스템이 Widget 또는 ViewModel 함수를 직접 호출할 필요는 없습니다.

## 전달받고 싶은 내용

- 실제 매치 내 명단 변경을 담당하는 클래스와 담당자
- 클라이언트 조회 경로와 이벤트 이름, 구독·해제 방법
- 이벤트 발생 시 현재 목록이 갱신되어 있는지 여부
- 재접속·맵 전환 시 처리 규칙

## 완료 확인

- [ ] 퇴장 후 클라이언트의 현재 목록에 해당 플레이어가 남지 않습니다.
- [ ] HUD를 나중에 생성해도 현재 명단을 복원할 수 있습니다.
- [ ] 팀 정보가 늦게 수신되어도 팀 변경 알림으로 목록이 복원됩니다.
