# HUD 연동 요청 — 경험치와 플레이어 레벨

작성일: 2026-10-25  
대상: 플레이어 진행 / 경험치·레벨 담당자

## 목적

내 경험치바와 레벨, 팀원 목록의 각 팀원 레벨을 표시하기 위한 데이터 제공 요청입니다.

## 현재 확인한 구조

- `UNF_PlayerStatusViewModel`에는 `Level`, `Experience`, `RequiredExperience`와 `UpdateProgression()`이 있습니다.
- 현재 VM에는 실제 진행 모델을 조회·구독하는 연결이 없습니다.
- `UNF_BuildComponent`에는 `PlayerLevel`과 Getter가 있지만 진행 데이터의 원본 여부가 확정되지 않았고, 복제는 `COND_OwnerOnly`입니다.
- 따라서 이 빌드 값을 다른 클라이언트의 팀원 레벨로 바로 사용할 수 없습니다.

위 내용은 작성일의 C++ 소스 기준입니다. 별도 Blueprint 전용 진행 시스템이 있다면 그 조회 경로를 알려주세요.

## 요청 사항 — 실시간 데이터

| 정보 | 필요한 조회 범위 |
|---|---|
| 현재 플레이어 레벨 | 내 레벨과 각 팀원 레벨 |
| 현재 경험치 | 내 경험치 |
| 다음 레벨 필요 경험치 | 내 경험치바 계산 |

1. 위 값을 읽을 Getter 또는 한 번에 읽는 Snapshot을 제공해주세요.
2. 경험치·레벨 변경을 구독할 수 있는 알림을 제공해주세요. GAS Attribute로 관리한다면 기존 ASC 변경 이벤트를 사용하겠습니다.
3. 변경이 클라이언트에 복제된 시점에도 알림을 받을 수 있어야 합니다.
4. 다른 팀원의 레벨은 해당 클라이언트에서 읽을 수 있어야 합니다. 구체적인 복제 방식은 담당 파트에서 결정해주세요.
5. UI가 늦게 생성되거나 리스폰 후 다시 연결되어도 현재값을 조회할 수 있어야 합니다.

## 요청 사항 — 값의 의미와 정적 데이터

- 현재 경험치가 해당 레벨 내 누적값인지, 전체 누적 경험치인지 알려주세요.
- 필요 경험치가 이번 레벨의 구간 크기인지, 다음 레벨의 누적 기준값인지 알려주세요.
- 최대 레벨에서 필요 경험치와 경험치바를 어떻게 해석해야 하는지 알려주세요.
- 레벨별 필요 경험치를 DataAsset 또는 테이블로 관리한다면 해당 원본과 조회 경로를 알려주세요. 원본이 없다면 진행 담당 데이터에 마련해주세요.
- 실제 현재 레벨과 경험치는 플레이어별 실시간 모델에서 제공해주세요. DataAsset에는 정적 성장 규칙을 보관하면 됩니다.

빌드 시스템과 HUD가 서로 다른 레벨을 원본으로 사용하지 않도록, 진행 상태의 기준 모델을 명확히 알려주세요.

## 데이터 흐름과 UI 담당 범위

```text
진행 모델의 현재 상태 + 필요 시 성장 DataAsset
    → PlayerStatusViewModel / TeamMemberViewModel
    → FieldNotify
    → 내 경험치·레벨 / 팀원 레벨 표시
```

UI에서 Getter 조회와 변경 이벤트 구독, 텍스트·경험치 비율 변환을 구현합니다. 기존 `UpdateProgression()`은 VM 내부 갱신에 사용할 수 있습니다. 진행 모델에서 이 함수나 Widget을 직접 호출할 필요는 없습니다.
